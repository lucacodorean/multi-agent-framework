# prompts

The prompts driving work in this repository, and the deliverables they produced. Working
material: outside the knowledge base, binding nothing, kept as the record of why the tree looks
the way it does.

**No format is prescribed.** Write the input in whatever shape it arrives in — a tracker export,
pasted tickets, a screenshot of a board, an informal list, or a plain brief. The
`tracker-intake` skill normalizes work items into an orchestrator-ready backlog and gates the
ones that are incomplete, kicking them back with the missing fields named; that feedback loop is
the quality control, and a template in front of it would only narrow what the skill already
accepts.

Two things no adapter can infer from the content, so they are worth a line when they apply:

- where the input came from, and whether it can be re-fetched — a query that can be re-run is a
  snapshot; a paste or a verbal decision is the only record there will ever be;
- anything that constrains the work without being work itself — a standing ruling, an
  architectural constraint, a deadline. Absent that separation it lands inside an item and
  becomes a requirement nobody agreed to.

Conventions that do apply here:

- **Naming:** `YYYY-MM-DD-<imperative-slug>.md`. A deliverable produced by a prompt keeps the
  prompt's date and says what it is: `YYYY-MM-DD-<slug>-analysis.md`.
- **Chaining:** a prompt whose output feeds another says so, and the consumer names its input.
  The chain is the traceability record.
