# Local runtime — DDEV

The only local runtime. System description: `docs/architecture.md`. Commands:
`docs/runbook.md`.

## Services — DDEV project `oir-flow`

| service | what | source |
|---|---|---|
| web | nginx-fpm, PHP 8.5, Node 22, Mailpit :8025 | `.ddev/config.yaml` |
| db | PostgreSQL 16 | `.ddev/config.yaml` |
| redis | `redis:7.4.10-bookworm`, pinned in `.ddev/.env.redis` over the add-on's floating tag | `infra/ddev/bootstrap.sh` |
| engine | `python:3.12.13-slim-bookworm` + libreoffice-writer; `uvicorn engine.app.main:app`; internal-only `expose: 8000`, no router entry, no host port; bind-mounts `engine/` read-only | `infra/shared/engine/Dockerfile`, `infra/ddev/docker-compose.engine.yaml` |
| queue-worker | supervised `queue:listen` daemon in the web container | `infra/ddev/daemons/queue-worker.sh`, `infra/ddev/config.daemons.yaml` |

## Generation

- Source of truth is `infra/ddev/`; `.ddev/` is generated by `infra/ddev/bootstrap.sh`.
  Edit the source, re-run bootstrap — never hand-edit a generated copy.
- Nothing under `infra/ddev/` is read by another runtime or by a gate; runtime-agnostic
  inputs live in `infra/shared/` (`docs/architecture.md` § Runtimes).
- Bootstrap installs the Redis add-on, then writes `.ddev/redis/redis.conf` as the
  `#ddev-generated` marker line followed by `infra/shared/redis/redis.conf`; the marker is
  a DDEV convention and is not stored in the shared file. Without it an add-on upgrade
  reverts the eviction policy.
- Bootstrap assembles the engine build directory `.ddev/engine-build/` by copying both
  `infra/shared/engine/Dockerfile` and `infra/shared/engine/requirements.txt`; the image
  carries the runtime only, the application source is the bind mount. CI builds the same
  image from the same two files (`docs/ci/gitlab.md`).

## Exposure

- Project ports bind every interface (`bind_all_interfaces`); the shared router needs the
  host-global `ddev config global --router-bind-all-interfaces=true`.
- Postgres is published at `0.0.0.0:5432` (`host_db_port`, `infra/ddev/config.stub.yaml`).
  Do not co-locate with another runtime publishing the same host port.
- The engine is the one service published nowhere: adding `ports:`, `HTTP_EXPOSE`,
  `HTTPS_EXPOSE` or `VIRTUAL_HOST` to it contradicts `contract/engine.openapi.yaml`
  `servers` (`infra/ddev/docker-compose.engine.yaml`).
- URLs: app `http://oir-flow.ddev.site` · Mailpit `http://oir-flow.ddev.site:8025` ·
  panels `/console` and `/{tenant-slug}`.

## Engine connection and auth

- `ENGINE_URL=http://engine:8000` and `ENGINE_KEY=dev-only-insecure-engine-key` are DDEV
  web-container defaults (`infra/ddev/config.stub.yaml`,
  `infra/ddev/docker-compose.engine.yaml`); the platform reads them through
  `config/engine.php`. Override per machine with `.ddev/.env` before `ddev start`.
- That key is a published development value, never a secret. The guard behaviour of an
  unconfigured deployment is in `docs/architecture.md` § Contract boundary.
